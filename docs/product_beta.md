# quant.ai 个人研究台试用说明

这次试用验证一个具体需求：持有美股、平时没时间整理资料的人，是否愿意持续使用一份围绕自己持仓的研究简报。

## 启动与体验

安装项目后，在项目目录运行：

```bash
quant-ai start --demo --lang zh --open
```

演示价格和初始持仓均为人为构造，日期固定，不能用于判断真实市场。数据独立保存在 `.quant-demo/`；再次启动保留演示中的持仓修改。报告、导出文件和复制文本均保留模拟数据说明。

真实研究使用：

```bash
quant-ai start --lang zh --open
```

默认优先读取 `configs/my.yaml`，不存在时使用 `configs/default.yaml`。`--config <路径>` 可指定另一份配置，`--port` 可更换端口。`--demo` 与 `--config` 不能同时使用。按 Ctrl+C 停止服务。

1. 添加自选代码，可用逗号或空格分隔，每次最多 50 个。
2. 按需记录持仓股数、每股平均成本和备注。同一代码再次保存会替换该条持仓，可通过「编辑」修改；「移除」删除该条记账记录。
3. 点击「生成研究简报」。首次真实数据下载可能需要几分钟，页面会显示任务状态。修改自选或持仓后需要重新生成。
4. 在页面阅读报告，或下载自包含 HTML 文件。
5. 选择研究问题，复制完整简报，粘贴到自己的 AI 助手里讨论。复制内容包含你的持仓，请自行决定是否分享。

自选和持仓与 MCP 管理工具共用同一配置指定的文件。浏览器通过 `holdings.py` 读写，不改写个人股票池 CSV。损坏的 JSON 文件会显示错误并阻止保存。

## 当前产品边界

- 本机单用户产品。服务监听回环地址；没有在线多租户账号、云端持仓同步、支付或公共发布。
- 配置启用 `dashboard_security` 时，研究台要求访问令牌。新研究台接口和报告导出遵循现有 API 认证；令牌只保存在当前页面内存。旧控制台和旧报告页面仍沿用原来的访问行为，因此现有服务不应被当成可公开托管的安全边界。
- 项目生成可核对的研究事实，AI 的综合分析在用户自己的客户端发生。没有新增 LLM API、模型计费或网页聊天接口。
- 实时报价尽力获取，可能退回最新收盘价。报告显示数据日期；数据获取失败会显示状态提示，已存在的报告在生成任务异常时保留。
- 仅供研究与学习，不构成投资建议；不下单、不审批、不连接券商。

## 第一批用户怎么验证

先邀请 5 位实际研究美股的人，各自本机安装，不集中收集他们的持仓。先让他们独立完成首次简报，再观察两周。

需要记录的是真实行为：能否独立启动、首次简报耗时、是否在不同日期主动回来、哪些内容会复制给 AI、遇到哪些错误，以及每位用户需要多少维护时间。使用者口头说「不错」只能作为反馈，不能当作付费验证。

两周后，向持续使用的人提出明确的服务范围与收费试验，核实他们愿意为何种持续交付付钱。售价、转化率和收入目前都未验证。商业收费前需核实所用行情和资讯的数据授权及成本。

首批试用反馈应决定下一步做一键安装、报告交付还是其他功能；当前不预设增加模型、支付或复杂云端服务能改善留存。
